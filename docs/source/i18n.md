# Langues de l'interface (traduction)

*Public : développeur contributeur, traducteur. Statut : **partiellement implémenté** —
l'infrastructure existe (HP-I18N-001) ; le catalogue anglais n'est traduit que pour quelques
écrans (HP-I18N-002).*

## Décision : le français reste la langue source

Les ~2 400 appels `tr()` de `apps/desktop` sont écrits en français. Passer l'anglais en langue
source (usage courant de Qt) obligerait à réécrire toutes ces chaînes, sans bénéfice pour
l'utilisateur : un catalogue `fr → en` donne le même résultat. Conséquences :

- il n'y a **pas** de fichier `.ts` pour le français : les textes du code s'affichent tels quels ;
- chaque autre langue est un fichier `apps/desktop/i18n/openstitch_<code>.ts` ; aujourd'hui
  seulement `openstitch_en.ts` ;
- une chaîne non traduite (entrée `type="unfinished"`) s'affiche en **français**, jamais vide.

## Fonctionnement

- `qt_add_translations` (dans `apps/desktop/CMakeLists.txt`) compile chaque `.ts` en `.qm` avec
  `lrelease` et l'embarque sous `:/i18n/openstitch_<code>.qm`. Qt6 `LinguistTools` est requis.
- `app_language.*` : `loadLanguagePreference()` lit la clé `ui/language` (`system`, `fr`, `en` ;
  toute autre valeur vaut `system`), `resolveLanguage()` choisit la langue effective (système
  français → `fr`, toute autre langue → `en`), `installTranslators()` installe la traduction de
  Qt (boutons standard, via `qtbase_<code>.qm`) et celle de l'application.
- `main.cpp` applique la langue **au démarrage**. Le dialogue *Paramètres → Interface → Langue*
  enregistre la préférence ; elle est prise en compte au **prochain démarrage** (le changement à
  chaud demanderait de reconstruire toutes les fenêtres ouvertes).
- `windeployqt --translations fr,en` déploie les traductions de Qt avec l'exécutable.

## Ajouter ou mettre à jour des traductions

```powershell
cmake --build --preset msvc-debug --target update_translations   # re-scanne les sources, met à jour les .ts
```

Ouvrir `apps/desktop/i18n/openstitch_en.ts` dans *Qt Linguist* (ou l'éditer) : une entrée
traduite perd son attribut `type="unfinished"`. Une nouvelle langue : ajouter le `.ts` à
`TS_FILES`, le code à `supportedLanguages()` et une entrée au sélecteur de
`settings_dialog.cpp`.

## Reste à faire

- **HP-I18N-002** (fait pour les chaînes existantes) : les 2 260 entrées de `openstitch_en.ts`
  sont traduites ; `test_app_language` (`englishCatalogIsComplete`) échoue s'il reste une entrée
  `unfinished`, une traduction vide ou un caractère typiquement français. Toute chaîne ajoutée
  ensuite par `tr()` doit être re-extraite (`update_translations`) puis traduite, sinon ce test
  échoue.
- **HP-I18N-001.a** : messages du cœur (`Finding::message`, erreurs `Result`) : identifiants et
  paramètres côté cœur, texte côté desktop. Tant que ce n'est pas fait, ces messages restent en
  français quelle que soit la langue choisie.
